Qu'est-ce que Angular ?

  • Framework Javascript complet
  • Architecture basée sur les composants
  • Inclut tout !
    • Routing
    • HTML
    • CSS
    • Forms
    • etc

Commandes de bases

  • Démarrage du serveur : ng serve
  • Création de component : ng generate component nom-du-component
    • --standalone : crée un componant standalone
    • --skip-tests : ne crée pas le fichier de test
    • --inline-template : ne crée pas de fichier .html, le template est dans .ts
    • --inline-style : ne crée pas de fichier .css, le style est dans .ts
    • --flat : ne crée pas de dossier pour le composant
  • Création de service : ng generate service nom-du-service

Composants et services, c'est quoi ?

  • Composants
    • Genre d'objet
    • Contient le .ts, .html, .css...
    • Modulaire et réutilisable
    • Communications avec d'autres composants
  • Services
    • Classe réutilisable
    • Gère les appels API et la logique commune
    • Ajoutée via le constructeur

Standalone VS non-standalone

  • Non-standalone
    • Composants doivent être déclaré dans NgModule
    • Ont besoin d'un fichier app.module.ts
    • Dépendances gérées directement dans le module
  • Standalone
    • Autonome, donc pas besoin de NgModule
    • Importent directement leurs propres dépendances
    • Simplifient l'architecture de l'application
    • Résumé : n'a pas besoin d'être dans un module, peut fonctionner seul

Les différents fichiers

  • Fichier .ts
    • Sorte de controller
    • Gestion des propriétés
    • Gestion des méthodes
    • Communications avec d'autres composants
  • Fichier .html
    • Fichier template
  • Fichier .css
    • Fichier style
  • Fichier .specs.ts
    • Fichier de tests unitaires

En résumé :

  1. Création de component :
    • ng generate component name --standalone
  2. Confirguration des fichiers :
    • name.ts
    • app.routes.ts
    • name.html
    • name.css

Qu'est-ce que API REST ?

  • REST : Representational State Transfer
  • Architecture pour communication client-serveur
  • Utilise le protocole : HTTP
  • Échange de données : JSON
  • Stateless : chaque requête est indépendante

Méthodes HTTP

  • GET : récupérer des données
  • POST : créer une nouvelle ressource
  • PUT : mettre à jour une ressource complète
  • PATCH : mettre à jour partiellement une ressource
  • DELETE : supprimer une ressource

Structure d'une URL REST

  • Endpoint : l'URL d'accès à la ressource
  • Formats : /api/ressources ou /api/ressources/id
  • Exemples :
    • GET api/users : liste tous les utilisateurs
    • GET /api/users/1 : récupère l'utilisateur 1
    • POST api/users : crée un nouvel utilisateur
    • PUT /api/users/1 : modifie l'utilisateur 1
    • DELETE /api/users/1 : supprime l'utilisateur 1

Principes REST

  • Client-serveur : séparation des responsabilités
  • Sans état : pas de session côté serveur
  • Cacheable : les réponses peuvent être mises en cache
  • Uniforme : utilisation standard des méthodes HTTP
  • Couches : architecture modulaire

Dans Angular

  • Utilise HttpClient pour faire des appels
  • Les requêtes retournent des Observables
  • Gérées dans les services

En résumé :

  1. REST : architecture standardisée pour les APIs
  2. Verbes HTTP pour les actions CRUD
  3. JSON pour l'échange de données

Qu'est-ce que Laravel ?

  • Framework PHP
  • Architecture MVC (Model-View-Controller)
  • Inclut tout !
    • Routing
    • Authentification
    • API
    • Base de données
    • etc

API REST avec Laravel

  • Routes API
    • Définies dans routes/api.php
    • Retournent du JSON

Commandes de base

  • Démarrage du serveur : php artisan serve
  • Création de controller : php artisan make:controller NomController
    • --resource : crée un controller avec méthodes CRUD
    • --api : crée un controller API (sans create/edit)
  • Création de model : php artisan make:model Nom
    • -m : crée aussi la migration
    • -c : crée aussi le controller
    • -mcr : crée model + migration + controller resource
  • Création de migration : php artisan make:migration create_table_name
  • Exécuter les migrations : php artisan migrate
    • php artisan migrate:fresh : re-exécute toute la migration
    • php artisan migrate:fresh : re-exécute toute la migration et lance les seeders

Architecture MVC

  • Modèle
    • Représente les données (table de base de données)
    • Situé dans app/Models/
    • Gère les relations entre tables
  • Vue
    • Interface utilisateur HTML
    • Utilise Blade
    • Situé dans resources/views/
  • Contrôleur
    • Logique de l'application
    • Fait le lien entre Model et View
    • Situé dans app/Http/Controllers/
    • Traite les requêtes HTTP

Controller API

  • Pas de méthodes create() et edit()
  • Méthodes principales :
    • index() : GET /api/users (liste)
    • store() : POST /api/users (créer)
    • show($id) : GET /api/users/id (afficher)
    • update($id) : PUT/PATCH /api/users/id (modifier)
    • destroy($id) : DELETE /api/users/id (supprimer)

Validation

  • Valider les données entrantes
  • Dans le controller avec validate()
  • Form Request : php artisan make:request NomRequest
  • Règles courantes :
    • required : champ obligatoire
    • email : format email valide
    • unique:table : valeur unique dans la table
    • min:x / max:x : longueur min/max

Eloquent ORM (Object-Relational Mapping)

  • Système pour interagir avec la base de données
  • Opérations principales :
    • all() : récupérer tous les enregistrements
    • find($id) : trouver par ID
    • where() : filtrer les résultats
    • create() : créer un enregistrement
    • update() : mettre à jour
    • delete() : supprimer
  • Relations :
    • hasMany() : un vers plusieurs
    • belongsTo() : appartient à
    • belongsToMany() : plusieurs vers plusieurs

En résumé : API REST Laravel

  1. Création d'une API complète :
    • php artisan make:model User -mcr
      • (Model + Migration + Controller)
    • php artisan make:controller UserController --api
      • (juste controller API)
  2. Fichiers à configurer :
    • routes/api.php : définir les routes
    • app/Models/User.php : définir le modèle
    • app/Http/Controllers/UserController.php : logique métier
    • database/migrations/ : structure de la table
  3. Lancer l'API :
    • php artisan migrate : créer les tables
    • php artisan serve : démarrer le serveur
    • Accès : http://localhost:8000/api/users

Composants Standalone - Vue d'ensemble

  • Approche moderne d'Angular (v14+)
  • Autonomes : pas besoin de NgModule
  • Simplifient l'architecture
  • Recommandés depuis Angular 15+

Création

  • Commande : ng generate component nom --standalone
  • Ou version courte : ng g c nom --standalone

Structure du fichier .ts

  • Propriété standalone: true obligatoire
  • Imports directs dans le décorateur
    • CommonModule (ngIf, ngFor, etc.)
    • FormsModule (ngModel)
    • RouterModule (routerLink)
    • Autres composants standalone

Avantages VS Non-Standalone

  • Moins de code boilerplate
  • Plus simple à comprendre
  • Meilleure optimisation (tree-shaking)
  • Lazy-loading facilité
  • Plus facile à tester
  • Pas besoin de app.module.ts

Imports courants

  • CommonModule : directives de base (ngIf, ngFor, ngClass, etc.)
  • FormsModule : formulaires template-driven (ngModel)
  • ReactiveFormsModule : formulaires réactifs
  • RouterModule : routing (routerLink, router-outlet)
  • HttpClientModule : requêtes HTTP (via provideHttpClient)

Configuration du Routing

  • Fichier : app.routes.ts
  • Import direct du composant standalone
  • Pas besoin de module intermédiaire
  • Lazy-loading simplifié avec loadComponent

Bootstrap de l'application

  • Fichier : main.ts
  • Utilise bootstrapApplication()
  • Configuration dans app.config.ts
  • Providers globaux (HttpClient, Router, etc.)

Communication entre composants

  • @Input() : recevoir des données du parent
  • @Output() : émettre des événements vers le parent
  • Services : partager des données (injectable dans standalone)
  • Pas de différence avec les non-standalone

En résumé

  1. Création :
    • ng g c nom --standalone
  2. Configuration essentielle :
    • standalone: true dans @Component
    • imports: [...] pour les dépendances
    • app.routes.ts pour le routing
  3. Avantage principal :
    • Simplicité : pas de NgModule à gérer

Responsive Design

  • Approche adaptative pour tous les écrans
  • Mobile-first : priorité aux petits écrans
  • Expérience utilisateur optimale
  • Essentiel en développement moderne

Media Queries

  • Syntaxe : @media (condition) ...
  • Breakpoints courants :
    • Mobile : max-width: 768px
    • Tablette : 769px - 1024px
    • Desktop : min-width: 1025px

CSS Grid & Flexbox

  • Grid : layout en 2D (lignes + colonnes)
  • Flexbox : layout en 1D (ligne ou colonne)
  • Auto-ajustement avec auto-fit/auto-fill
  • Alignement facile avec justify-content et align-items

Git & GitHub

  • Git : système de contrôle de version distribué
  • GitHub : plateforme d'hébergement de code
  • Collaboration et suivi des modifications

Commandes de base Git

  • git init : initialiser un dépôt
  • git clone <url> : cloner un dépôt distant
  • git status : voir l'état des fichiers
  • git log : historique des commits

Workflow de commit

  • git add . : ajouter tous les fichiers modifiés
  • git commit -m "message" : créer un commit
  • Message descriptif et clair obligatoire

Fonctionnalités GitHub

  • Pull Requests : proposer des modifications
  • Issues : suivi des bugs et tâches
  • Actions : CI/CD automatisé
  • Pages : hébergement de sites statiques
  • Fork : copier un dépôt pour contribuer

Bonnes pratiques

  • Commits fréquents et atomiques
  • Messages clairs : "Ajoute feature X" ou "Corrige bug Y"
  • Utiliser .gitignore pour exclure fichiers inutiles
  • Brancher pour chaque nouvelle fonctionnalité
  • Pull avant de push pour éviter conflits

En résumé

  1. Workflow de base :
    • git add → git commit → git push
    • git pull pour synchroniser
  2. Collaboration :
    • Branches pour isoler le travail
    • Pull Requests pour valider les changements
    • Merge pour intégrer
  3. Avantage principal :
    • Historique complet et travail collaboratif efficace

Node.js

  • Runtime JavaScript côté serveur
  • Non-bloquant et asynchrone
  • Écosystème riche avec npm

Installation & Vérification

  • Télécharger depuis nodejs.org
  • Vérifier : node --version ou node -v
  • npm inclus : npm --version ou npm -v
  • Recommandé : version LTS (Long Term Support)

NPM - Node Package Manager

  • npm init : créer un package.json
  • npm install <package> : installer un package
  • npm install : installer toutes les dépendances
  • npm uninstall <package> : désinstaller
  • npm update : mettre à jour les packages

Package.json

  • Fichier de configuration du projet
  • dependencies : packages de production
  • devDependencies : packages de développement
  • scripts : commandes personnalisées
    • "start": "node app.js"
    • "dev": "nodemon app.js"

Modules & Imports

  • CommonJS : const express = require('express')
  • ES Modules : import express from 'express'
  • Modules natifs : fs, path, http, etc.
  • module.exports pour exporter

Frameworks populaires

  • Express.js : framework web minimaliste
  • NestJS : framework structuré (TypeScript)
  • Fastify : performant et moderne
  • Koa : léger, par les créateurs d'Express

Asynchrone & Callbacks

  • Callbacks : fonctions passées en paramètre
  • Promises : .then() et .catch()
  • Async/Await : syntaxe moderne et lisible
  • Event Loop pour la gestion non-bloquante

Outils de développement

  • nodemon : redémarrage auto lors des modifications
  • dotenv : gestion des variables d'environnement
  • PM2 : gestionnaire de processus en production
  • ESLint : analyse statique du code

En résumé

  1. Démarrage :
    • npm init pour initialiser
    • npm install pour les dépendances
    • node app.js pour exécuter
  2. Concepts clés :
    • Asynchrone avec async/await
    • Modules pour structurer le code
    • npm pour gérer les packages
  3. Avantage principal :
    • JavaScript partout : front-end et back-end
